  Why: the matchmaking guard string (Citadel_StartMatchmaking_UnverifiedPGI, added 2026-07-31) reads: "Unable to enter
  matchmaking while any party member is running Tools-mode, or has unsupported changes to the following sections of their
  'gameinfo.gi': Engine2, MaterialSystem2, NetworkSystem, Particles, RenderSystem, SceneSystem, WorldRenderer". The client
  already sends pgi_hash/pgi_version (CMsgCitadelClientHello) and the GC answers pgi_verified. Not enforced as of
  2026-10-05, but ConVars are explicitly NOT on the list, so this config now keeps all tuning in ConVars and leaves the
  seven guarded sections byte-identical to Valve's stock gameinfo.gi (GameTracking e0b9830, build 6746).
  Reverted upstream (Sqooky) engine edits, 59 keys: Particles 6, RenderSystem 10 (incl. IndexBufferPoolSizeMB 128->32,
  MinStreamingPoolSizeMB 2048->1024, the six stock Vulkan* keys restored), SceneSystem 35 (shadow/fog buffer sizes back
  to stock, VolumetricFog/CubemapFog/NonTexturedGradientFog back to 1, HDRFrameBuffer and ~25 dll vars dropped),
  WorldRenderer 8 (GrassCastsShadows back to 1, Aggregate*/EnvironmentMapCacheSize dropped).
  Expected effect: small. The ConVars block still disables sun shadows (csm_*), SSAO, bloom etc.; what comes back is
  Valve's default buffer sizing and fog paths. Re-measure 1% lows; if they drop noticeably, the fix is more ConVars,
